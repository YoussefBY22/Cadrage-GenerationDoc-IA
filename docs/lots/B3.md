## Fait
- `app/retrieval/` : `textnorm.tokenize`, `chunking.chunk_document` (+ `indexed_text`, `estimate_tokens`), `bm25.BM25Index`, `fusion.rrf`, `hybrid.HybridRetriever` (+ Protocol `ChunkSource`), `rerank.{Reranker,NoopReranker}`.

- Pipeline `search` : une liste BM25 + une liste vectorielle par requête (pool 50) → RRF (k=60) → reranker sur les 30 premiers → plafond ceil(k/2) par document → dédoublonnage (> 50 % de 5-grammes de mots communs, même document) → étiquettes P1..Pk. `ranks` = meilleur rang par source.

## Limites
- Plafond de diversité strict : un dossier à un seul document ne renvoie que ceil(k/2) passages.
- Un seul `lang` par récupérateur pour la racinisation (fr par défaut) ; les mots vides FR+EN sont toujours retirés.
- Estimation des jetons non calibrée (ceil(mots × 1,3)). Le chevauchement s'ajoute au texte neuf : le chunk reste ≤ max_tokens.
- Index BM25 reconstruit au premier appel après `invalidate` (itère tous les passages du dossier).

## Écarts aux contrats de 06

- Idf BM25 de type Lucene : ln(1 + (N − n + 0,5)/(n + 0,5)).

## Pour comprendre
Le BM25 est un bibliothécaire qui cherche les mots exacts (rares = précieux), la recherche vectorielle un collègue qui cherche « ce qui ressemble ». RRF leur demande chacun un classement et ne retient que les rangs : un passage cité haut par les deux gagne, sans comparer des scores incomparables. Enfin on évite que dix passages viennent du même document.
