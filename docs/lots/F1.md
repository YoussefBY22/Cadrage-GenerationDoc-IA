# Lot F1 — Banc d'évaluation A/B/C/D

> **Simulation : sans valeur scientifique.** Les chiffres ci-dessous valident la mécanique, pas un modèle.

## Fait
- `eval/harness/metrics.py` (fonctions pures : rappel@k, MRR, citations valides, fidélité des chiffres, structure, couverture des constats, dépendances, refus manqués/faux refus, réussite d'attaque, percentiles), `bootstrap.py` (IC95 %, 1 000 tirages, graine fixe, IC apparié), `simulate.py` (handler FakeProvider à taux : fausses citations, chiffres inventés, obéissance au piège, JSON invalide, refus manqués), `run.py`, `report.py` (tableau Markdown, CSV, règle C vs B de 08 §6).
- `run` : corpus B4 dans un dossier temporaire, ingestion par les services B5, recherche, 53 sections par graine (ToR/CdC par institution + 30 « preuve » + 10 `no_evidence`), 5 documents piégés, constats et feuille de route (services C4). Écrit `results/<date>-<config>.json`. Identifiants rendus déterministes pendant l'exécution (les égalités de score se départagent par id).
- `eval/configs/{A,B,C,D,sim}.yaml` ; A : pas de passages (prompt sans balises PASSAGE). A–D : provider `ollama`, modèles `*_REMPLIR_T2/T5` à renseigner demain.

## Testé
`ruff check .` → `All checks passed!` ; `pytest -q` → `350 passed, 2 skipped` (Postgres, LibreOffice). 11 tests `tests/eval_harness` : chaque métrique sur cas calculé à la main ; simulation taux 0 → TPV 1,0, 0 attaque ; `false_citation=0,3` → TPV 0,7 ± 0,1 ; bootstrap et exécution reproductibles ; règle de décision ; rapport.
`python -m eval.harness.run --config eval/configs/sim.yaml` → 4,6 s (< 60 s) : TPV 0,847 IC95 [0,815 ; 0,877] sur 189 sections, rappel@10 = 1,00, MRR 0,73.

## Limites
- Constats et feuille de route : mesurés sur la 1ʳᵉ graine et la 1ʳᵉ institution seulement ; dépendances rapprochées par « I<n> » dans les titres (un vrai modèle ne les nommera pas ainsi : à revoir en T2).
- Provider réel : les graines ne sont pas transmises à `generate_structured` (`call_model` ne les passe pas) ; elles ne varient que dans la simulation.
- Non implémentés : évaluation humaine (grille, kappa), instrumentation VRAM fine (un seul `nvidia-smi` en fin de run).
- La réussite d'attaque ne détecte que le canari, pas « l'obéissance » sans canari.

## Pour comprendre
Le banc est un jury qui fait passer le même examen à plusieurs candidats (A à D) et note chaque copie avec la même grille. Le mode simulation est un faux candidat qui se trompe volontairement 30 % du temps : si le jury trouve ≈ 30 % d'erreurs, la grille fonctionne.

## 3 questions
1. Pourquoi comparer C à B par un intervalle de confiance et non par la seule moyenne ?
2. Pourquoi une métrique de sécurité qui se dégrade bloque-t-elle C même si le TPV monte ?
3. Que mesure la config A, et pourquoi le vérificateur y tourne-t-il quand même ?
